# 保鲜管家 FreshGuard · 前端（A 角色：前端交互）

物品保质期识别与提醒 —— 「拍一张储物架或冰箱内部的照片，系统识别物品、读出生产日期与保质期，
算出临期天数并给出提醒」。本仓库是其中的**前端交互侧**交付物。

选题要求的三件事在这里被拆成「看得见、点得动」的界面：
**认出是什么 → 归到哪一类 → 什么时候到期**，最后落到**临期看板**。

## 4. 日期归一化规则引擎（自研模块，`src/services/dateParser.ts`）

这是本角色承接的**纯逻辑**自研模块，17 条以上写法全部有断言覆盖（`npm run test:parser`）：

| 类别 | 已覆盖写法 | 用例 |
| --- | --- | --- |
| 标准日期 | `2026-08-20`、`2026.09.10`、`2026/11/03`、`2026年9月26日` | ①②④ |
| 紧凑喷码 | `20260915`、`20261003` | ③ |
| 只到月 | `有效期至 2027.03`（取当月最后一天） | ⑤ |
| 时长为单位 | `保质期 6 个月`、`有效期 24 个月`、`保质期 3 年`、`保质期 30 天` | ①②④⑥⑨ |
| 中文数字 | `保质期 十八个月` | ⑧ |
| 到期表述 | `保质期至 …`、`有效期至 …`、`此日期前使用 …`、`最佳食用期` | ②⑤⑦ |
| 无年份 | `保质期至 10月02日`（按最近未来年补齐） | ⑩ |
| 全角 | `２０２６．０７．１５` + `２个月` | ⑰ |
| 无标签裸日期 | 两串数字 → 按「最早 = 生产、最晚 = 到期」推断并告警 | ⑫ |
| 边界 | `2026-01-31` + 1 个月 → `2026-02-28`（月末夹取） | ⑯ |
| 矛盾 | 到期日早于生产日期 → 告警 | ⑱ |

### 降级与兜底策略（题目要求「错误兜底策略」）

1. **识别不出来就要说**：解析失败绝不返回空结果，一定带 `warnings` 文案，界面上是红色/黄色告警块
   （用例⑬⑬b⑭⑮：`failed` 模式必须带告警，测试里有断言强制这条不变量）。
2. **半自动而非全自动**：日期字段永远可编辑；人工改动即标记「日期已人工复核」，
   看板对未复核条目标出「未复核」角标。
3. **印刷位置找不到值**：命中「见包装 / 见盒身 / 见喷码 / 印于…」等提示词时，
   直接给出「日期印在包装其他位置，请人工填写」，而不是硬凑一个日期。
4. **不确定就降级到人**：置信度低于阈值 → 强制给候选点选；整图 0 目标 → 仍生成一条空白记录，
   让这条录入不凭空消失。
5. **比例 + 天数双规则**：短保品（90 天剩 15 天）按天数看还没到，按比例已经是临期，
   两条规则任一成立即判临期，避免短保品漏提醒。

## 5. 与 B 角色（模型部署）的接口契约

前端只依赖两个接口。在设置面板里填入地址并勾选「启用真实后端」即可切换，
**不改一行界面代码**；未填地址时走内置演示模式，保证 A 侧独立可演示。

```
POST {apiBase}/api/detect      multipart/form-data: file=<图片>
→ 200 {
    "objects": [{
      "id": "1",
      "label": "纯牛奶",
      "score": 0.93,
      "category": "drink",                     // food|fresh|drink|daily|medicine|stationery|other
      "box": { "x": 0.06, "y": 0.10, "w": 0.26, "h": 0.42 },   // 归一化 0~1
      "candidates": [ { "label": "纯牛奶", "score": 0.93, "category": "drink" } ]
    }],
    "costMs": 812,
    "engine": "yolov8n"
  }

POST {apiBase}/api/ocr         multipart/form-data: file=<图片>
→ 200 {
    "fullText": "…",
    "dateTexts": ["生产日期 2026-08-20", "保质期 6 个月"],
    "blocks": [ { "text": "…", "score": 0.97, "box": {…}, "isDateRegion": true } ],
    "costMs": 430,
    "engine": "rapidocr"
  }

GET  {apiBase}/api/health      → 200 任意内容（用于设置面板的连通性自检）
```

约定与容错：

- `box` 用**归一化坐标**，前端据此在照片上叠加框；缺字段会用默认值兜底而不是崩掉。
- 类别取值非法或缺失时按 `other` 处理。
- `blocks` 为空时，前端退化为「整图日期文本 → 按物品顺序分配」，并给出告警。
- 单个接口报错不会中断批量：该张标记失败、继续下一张（模块 9 的要求）。
- 跨域：`vite.config.ts` 里预留了 `/api` 代理配置，注释打开即可免跨域联调。

## 7. 已知限制

1. **本机 npm 环境**：本机 npm 的 esbuild `postinstall` 会报 `EBUSY`（沙箱下 spawnSync 争用），
   但 `@esbuild/win32-x64` 二进制本身正常。若重装依赖请用
   `npm install --ignore-scripts`，随后 `npx esbuild --version` 应输出 `0.21.5`。
2. **演示模式的识别结果是模拟的**：由图片内容派生的稳定随机种子决定，用于界面评审与联调前自测，
   不代表真实模型精度。接上 B 角色的后端即为真实结果。
3. **示例场景图是程序化生成的示意图**（`scenario.ts`），不是真实照片 —— 好处是检测框与物品位置
   严格对齐、离线可用、不依赖外部图片资源。
4. 数据存在浏览器 localStorage，不含账号体系与多端同步；清理浏览器数据会清空清单。
5. 相机调用依赖浏览器与 HTTPS/localhost 环境；HTTP 域名下浏览器会禁用摄像头，此时仍可从相册选图。
